# AI Agent 编程实践指南

开工前，先想清楚用户要完成什么，以及打算用什么证据判断任务完成。根据手头的任务，选一条路径即可。

| 我现在要做什么？ | 从哪里开始？ |
| --- | --- |
| 我有一个产品或工具的想法，想判断它值不值得做。 | [构思新项目](guides/new-project.md) · 找出关键假设，设计最小实验，用结果决定下一步。 |
| 我需要在已有代码库里修 bug、加功能、改性能或重构。 | [开发已有项目](guides/existing-project.md) · 确认当前行为，写下验收条件，从用户入口验证改动。 |

两份指南都附有可以直接复制的任务提示词。把示例换成自己的输入和预期结果。例如，修复导出重试问题时，可以要求 Agent 用同一批订单触发重试，再打开导出文件，核对每个订单号是否只出现一次。

当同一条意见反复出现在代码审查中，两份指南也能帮你决定该改哪里。启动命令难找，可以写进 `AGENTS.md`；模块依赖越界，可以加 lint 规则；重复导出导致数据出错，可以把复现步骤写成回归测试。

## 灵感来源

Lauren Tan（@poteto）在演讲中分享了她如何整理代码库、把反复出现的错误变成可执行检查，以及让 Agent 在运行中的应用里验证结果。这两份指南将这些做法整理成个人工作步骤，并加入了产品试验和任务示例。[观看演讲《All Code Is Slop (Except Mine)》](https://www.youtube.com/watch?v=O_zcc6Xl12g) · [阅读 Tan 的 pstack 工作流指南](https://github.com/cursor/plugins/blob/main/pstack/docs/guide/README.md)
